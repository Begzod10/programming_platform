# PC Guard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows agent blocks every non-allowlisted app on student PCs until the student's daily quota on the platform is met; teachers control PCs and read a report from a phone or Mac browser.

**Architecture:** The existing FastAPI backend is the hub. A new `pc_control` module computes lock state server-side (from `daily_quota_service`) and pushes it over a WebSocket. A C# .NET 8 agent (SYSTEM service plus a user-session shell app) enforces it. A new responsive page in the React teacher UI sends commands and shows the report.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, pytest (backend); C# .NET 8, xUnit, WPF (agent); React 19, CRA Jest + Testing Library (console).

**Spec:** `docs/superpowers/specs/2026-10-23-pc-guard-design.md`

The plan has three parts that each ship usable software: **Part A** backend (Tasks 1-7), **Part B** Windows agent (Tasks 8-13), **Part C** teacher console (Tasks 14-15). Part A plus B already gives working blocking. Task 16 syncs the spec.

## Global Constraints

- Student PCs: Windows only; agent is C# .NET 8; guard service runs as SYSTEM; students use standard (non-admin) Windows accounts.
- Allowlist blocking mode; the server decides lock state, the agent never unlocks itself.
- Heartbeat every 30 seconds; offline fallback: keep cached rules for 10 minutes, then lock.
- Record only app name, start/end time, lock state, sign-in/out times. No screenshots, keystrokes, window titles or page contents. The browser URL is checked locally and never stored or uploaded.
- Device token is scoped to `/pc/*` and must not work on any student or teacher API.
- Student passwords are never stored on the PC.
- Lock state reuses `StudentDailyProgress.unlocked` via `daily_quota_service.get_today`; rest days and the enabled flag come from there. Do not re-implement quota math.
- Teacher endpoints use `Depends(get_current_teacher)` from `app/dependencies.py`.
- Out of scope: macOS/Linux agents, native phone apps, Telegram digests, screenshots, remote desktop, per-student allowlists, auto-update.

## Review Focus

1. A device token used on `/student/*` or `/teacher/*` must return 401/403, never act as the student (Task 3).
2. A teacher account trying to sign in on a PC must be refused with 403 (Task 3).
3. A student signing in on a device whose previous session never signed out (crash/power-off) must close the old session and open a new one (Task 3).
4. A quota unlock for a student with no open PC session must not error (Task 4).
5. Usage events with `ended_at` before `started_at`, or lasting over 12 hours, must be rejected, not stored (Task 6).
